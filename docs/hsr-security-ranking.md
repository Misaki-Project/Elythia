# スターレイルの本人確認・権限・実績ランキング

正式Elythia 2.0.0を基準にしたMisaki版hsrプラグイン用の変更です。本番imageと更新スクリプトの確定digestは変更しません。導入にはプラグイン変更と本体のポリシー変更の両方が必要です。

- `hsrUidLimit`: 0〜100の整数、既定1。同優先度ではmax。0では新規連携を拒否します。既存の確認済み連携は上限を下げても削除しません。
- `hsrRefreshIntervalMinutes`: 1〜1440分の整数、既定10。同優先度ではmin。本人確認済みUIDの所有者の実効ポリシーを参照し、Enka TTLを優先します。取得失敗も試行時刻を保存します。
- role-levelの数値ポリシー範囲にも使用できます。不正な値は拒否します。XPの監査ログや本体のモデレーションログの扱いは変更しません。
- 旧hsr migration 1〜3は変更せず、migration 4で既存登録を未確認として保存します。再認証まで公開・取得・ランキング対象にならず、UIDも占有しません。
- 紐づけコードは6文字で記号1文字以上を含みます。有効期限10分、最大10回試行、再発行は30秒待機です。ゲーム内のステータスメッセージにコード全体が含まれることを確認します。確認送信後はUIで最低60秒待機し、バックエンドの未反映応答ではTTLと60秒の長い方を優先します。
- UID公開は既定オフ、ステータスメッセージ公開・ランキング参加は既定オンです。プロフィール表示側のUID表示も既定オフです。設定は全連携UIDへ適用します。
- `/plugin/hsr/rankings`で確認済みローカルUIDの実績数を集計します。同数は同順位です。参加無効・削除・凍結・リモートユーザーは除外し、公開UIDだけを返します。取得日時を表示し、リアルタイムではないことを明示します。
- 本体のユーザー可視性判定を尊重します。旧peer形式の応答は所有確認・公開設定を保証できないため取り込みません。他サーバーへ渡った情報は相手のキャッシュ更新まで残る場合があります。

マージ、image公開、本番適用は別途確認が必要です。CI成功は本番動作確認やDB復元試験の代わりにはなりません。

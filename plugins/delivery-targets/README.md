# delivery-targets

ノートごとに、連合で配送するサーバーを絞るプラグインです。CherryPickの「連合配送の対象」を、Elythiaのプラグインとして移したものです。

- 投稿フォームのフッターのボタン (地球のアイコン) から、そのノートの配送先を選べます
  - **指定したサーバーにだけ配送**: 一覧にあるサーバーにだけ届けます
  - **指定したサーバーには配送しない**: 一覧にあるサーバーには届けません
- 指定しなければ、今までどおりすべてのサーバーへ配送し、照会も許します。サーバーを1つも選ばなかったときも同じです
- 配送先から外したサーバーには、ノートを配送せず、照会 (`/notes/:id`などのActivityPubの取得) されても見せません
- 絞ったノートはリレーへ流しません (リレーは受け取ったものを加盟する全サーバーへ配り直すため)
- 絞ったノートは、`/notes/:id`をWebページとして開かれたときもOGP (要約・添付・作者) を出しません

信頼できないサーバーへ配送しないための機能です。照会してきたサーバーは、署名を確かめられればそのサーバー、確かめられなければUser-Agentに書かれたサーバーとして判定します。

- **exclude**: 相手が分からない照会 (署名もUser-Agentのホストも無い) には見せるので、外したサーバーでも、匿名で照会すれば取得できます
- **include**: 相手が分からない照会には見せないので、指定したサーバーでも、匿名で照会すると取得できません
- User-Agentは相手が自由に書けるので、名乗りを偽れば判定を外れます。MisskeyとMastodonは既定でUser-Agentに自分のURLを入れるので、既知の制約として受け入れています

本体の`plugin.Definition.NoteDelivery`を使います。プラグインは利用者の指定を検証して保存し、配送と照会への適用は本体が行います。詳しい仕組みと制約は、本体の[プラグインの作者向けの文書](../../docs/plugins/authoring.md#ノートの配送先を絞る)にあります。

## 指定の形

`notes/create`の`pluginOptions["delivery-targets"]`に、次の形で送ります。

```json
{ "mode": "include", "hosts": ["misskey.example", "mastodon.example"] }
```

- `mode`は`include` (指定したサーバーにだけ) か`exclude` (指定したサーバーには配送しない)
- `hosts`は最大100件。小文字にし、IDNはpunycodeにそろえ、URLを渡したときはホストの部分だけを取ります。サブドメインは含めません (完全一致)
- 形の誤り (知らない`mode`、ホストとして読めない値、101件以上) は`INVALID_PARAM`になり、ノートは作られません
- サーバーを1つも指定しないと、どちらのモードでも何も絞らないので保存しません (指定が無いのと同じ)

## データ

`plugin_delivery_targets`のschemaに`note_targets`テーブルを作ります (ノートのIDごとに1行)。ノートを消しても行は残りますが、IDは使い回されないので、他のノートには効きません。

## 注意

- **このプラグインを無効にすると、絞り込みも止まります。** 本体は指定を持っていないので、無効にした後は、絞ったノートも通常どおりに配送・照会されます
- **無効にすると、投稿フォームのボタンも出なくなります。** 設定の`enabled: false`でバックエンドを止めても、frontendはビルドに含まれたまま読み込まれます。そのため、frontendは起動のときにバックエンドの`plugin/delivery-targets/available`を呼び、`available: true`が返ったときだけボタンを出します(返らなければ、選んで投稿したときに`INVALID_PARAM`で失敗するため)
- **下書きと予約投稿では使えません。** サーバーの下書き (`notes/drafts`) は`pluginOptions`を受け取らないので、投稿フォームは指定のある下書きの保存と予約投稿を止めます。端末に残る書きかけの投稿には、指定も残ります
- **shared inboxを共有するサーバーには、外しても届くことがあります。** 許すサーバーと外したサーバーの利用者が同じshared inboxを使っていると、そのinboxへは送ります (送らなければ許したサーバーにも届かないため)
- CherryPickから移行したDBの`note."deliveryTargets"`列は読みません。移行前のノートの指定は引き継がれません
- 削除 (`Delete`) は絞りません。中身を持たず、届いていないサーバーでは何も起きないためです

## 実連合のe2e

`e2e/`に、本物のMisskeyとMastodonを相手に、指定どおりに配送と照会が止まるかを確かめるテストがあります(#52)。`tests/federation/`のスタックに重ね、プラグイン入りのElythiaで回します。Actionsでは`misaki-delivery-targets-e2e`が、プラグインや本体の配送・照会のコードを変えたPRと手動のときに回します。

```bash
# 前提: frontend/built がある (pnpm build 済み)。Dockerが要る
plugins/delivery-targets/e2e/run.sh misskey
plugins/delivery-targets/e2e/run.sh mastodon
```

| 指定 | 相手のフォロワーへの配送 | 相手のサーバーからの照会 | 署名の無い照会 |
|---|---|---|---|
| 指定なし | 届く | 見える | 見える |
| includeに相手を入れる | 届く | 見える | 見えない |
| includeに別のサーバーだけを入れる | 届かない | 見えない | 見えない |
| excludeに相手を入れる | 届かない | 見えない | 見える |
| excludeに別のサーバーだけを入れる | 届く | 見える | 見える |

「届かない」は、後から投稿した絞っていないノートが相手に着き、Elythiaの配送のキューが空になった後も、相手のタイムラインに出ないことで判定します。
